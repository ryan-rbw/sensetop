# Running SenseTop Locally (Demo Mode)

You can run SenseTop on your laptop without a Raspberry Pi or Sense HAT hardware by using mocked sensor data. This is perfect for testing the UI, navigation, and features.

## Prerequisites

- Python 3.8 or higher
- Git (to clone the repository)
- A terminal that supports curses (Linux/macOS/WSL on Windows)

## Installation Steps

### 1. Clone the Repository

```bash
git clone https://github.com/ryan-rbw/sensetop.git
cd sensetop
```

### 2. Create a Virtual Environment (Recommended)

```bash
# Using venv
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Or using conda
conda create -n sensetop python=3.10
conda activate sensetop
```

### 3. Install Dependencies

```bash
# Install required packages
pip install -r requirements.txt

# Or if you want to include development tools
pip install -r requirements-dev.txt
```

### 4. Run the Demo

```bash
# Method 1: Use the convenient demo script
python run_local_demo.py

# Method 2: Run directly with Python
python -m sensetop

# Method 3: Use the Makefile
make run-demo
```

## What You'll See

The application will display:

1. **Dashboard View** - Real-time sensor data with mock values
   - Acceleration (X, Y, Z)
   - Temperature
   - Humidity
   - Atmospheric Pressure
   - CPU Temperature
   - Memory Usage

2. **Graphs View** - Historical data with trends
   - Sparklines showing sensor trends
   - Trend indicators (↑/→/↓)
   - Statistical summaries

3. **Alerts View** - Active alarm notifications
   - Real-time alarm display
   - Severity indicators (🔴 Critical, 🟡 Warning)
   - Acknowledgment support

4. **Settings View** - Threshold configuration
   - View threshold values for each sensor
   - Reset to defaults option
   - Navigate between sensor thresholds

## Keyboard Controls

### Navigation
| Key | Action |
|-----|--------|
| **1** | Dashboard view |
| **2** | Graphs view |
| **3** | Alerts view |
| **4** | Settings view |
| **h** or **?** | Help screen |
| **q** or **ESC** | Quit application |

### View-Specific Controls
| View | Key | Action |
|------|-----|--------|
| Dashboard | (auto-updates) | Shows live sensor data |
| Graphs | ↑/↓ or j/k | Navigate between graphs |
| Alerts | **a** | Acknowledge all alarms |
| Settings | ↑/↓ or j/k | Select sensor |
| Settings | **r** | Reset to defaults |

## Exploring the Features

### 1. Test the Dashboard
- Press `1` to view the main dashboard
- Watch the sensor values update in real-time
- Values are randomly generated by mocks to simulate real data

### 2. View Historical Data
- Press `2` to see the graphs view
- Use ↑/↓ or j/k to navigate between different sensors
- See sparkline graphs showing trends over time
- Watch trend indicators (↑→↓) for each sensor

### 3. Check Alarms
- Press `3` to go to the alerts view
- Alarms trigger when mock sensor values hit thresholds
- Critical alarms appear in red (🔴)
- Warning alarms appear in yellow (🟡)
- Press `a` to acknowledge all alarms

### 4. Review Thresholds
- Press `4` to view settings
- Use ↑/↓ to select different sensors
- View the configured min/max values
- See critical ranges for each sensor
- Press `r` to reset all to defaults

### 5. Read Documentation
- Press `h` or `?` to see complete keyboard shortcuts
- All controls and features are documented in help

## Sensor Mock Data

The mock sensors generate realistic-looking data:

- **Temperature**: Varies between 15-35°C (59-95°F)
- **Humidity**: Varies between 20-80%
- **Pressure**: Varies between 980-1050 hPa
- **Acceleration**: Random values within ±8g
- **CPU Temperature**: Varies between 45-75°C
- **Memory Usage**: Varies between 30-80%

Alarms will trigger when values approach or exceed threshold boundaries, allowing you to see the alarm system in action.

The application comes with sensible defaults:

| Sensor | Warning Range | Critical Range |
|--------|---------------|-----------------|

| Pressure | 950-1050 hPa | 850-1150 hPa |
| CPU Temp | 20-60°C | -10 to 95°C |
| Memory | 0-75% | 0-95% |

## Data Directories

When you run the app, it creates directories for:

- **~/.sensetop/config.json** - User configuration
- **~/.sensetop/thresholds.json** - Threshold settings
- **~/.sensetop/sensetop.log** - Application logs
- **~/.sensetop/exports/** - CSV exports (if you export data)

These are created automatically and won't interfere with your Raspberry Pi installation.

## Troubleshooting

### "ImportError: No module named 'sensetop'"
- Make sure you're in the project directory
- Make sure your virtual environment is activated
- Try: `pip install -e .`

### "ModuleNotFoundError: No module named 'curses'"
- On macOS: curses should be built-in
- On Windows: Use WSL (Windows Subsystem for Linux) or a Linux VM
- On Linux: Should be built-in with Python

### "Terminal is not wide enough"
- Resize your terminal to at least 80 columns wide
- Try running in fullscreen
- On macOS iTerm2: Increase window size

### Alarms not showing up
- Alarms only appear when sensor values exceed thresholds
- The mock data is random, so alarms appear intermittently
- Press `3` frequently to see if any alarms are active
- Check the Alerts view for the current active alarms
